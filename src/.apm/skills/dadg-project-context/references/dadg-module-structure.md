# DADG Module Structure — Folder Detail

Detailed sub-folder breakdown for each DADG content module.

## DellarteDellaGuerra (`../DellarteDellaGuerra`)

Main content module. Key sub-folders:

- `ModuleData/` — general XML (items, troops, settlements, etc.) and feature-specific subfolders (e.g. `CustomXml/cannons.xml`, `Cannons/`)
- `Prefabs/` — Bannerlord entity prefab XML (e.g. `cannons.xml`)
- `AssetSources/` — source art files (FBX, textures, etc.) before compilation
- `Assets/` — compiled geometry and texture packs (`.tpac` files)
- `RuntimeDataCache/` — compiled Bannerlord asset cache; **do not edit by hand**, regenerate via Modding Kit
- `ModuleSounds/` — OGG audio files (e.g. `Cannon/` subfolder)
- Music track assets also live here (OGG + `soundtrack.xml`)

## DellarteDellaGuerraMap (`../DellarteDellaGuerraMap`)

England campaign map module. Key sub-folders:

- `SceneObj/` + `SceneEdit/` — the England campaign map scene data
- `GUI/` — Gauntlet UI layouts, widgets, and SpriteData XML files (e.g. `DadgCannonsSpriteData.xml`, `DadgMainUISpriteParts/`)
- `Assets/GauntletUI/` — compiled UI atlas files (`.tpac`, e.g. `dadg_ui_cannon_1_tex.tpac`)
- `AssetSources/` — UI sprite source art
- `RuntimeDataCache/` — compiled asset cache (same convention as main module)
- `ModuleData/` — map & sandbox XML: characters, equipment sets, settlements

> **Note on `DadgMainUISpriteParts/`:** this is the SpriteParts source folder for the main DADG UI (character creation, campaign panels). It was renamed from `GUI/SpriteParts` to avoid BannerEdge conflicts when editing the cannon sprite atlas. Do not mix cannon icon PNGs into it.

## DellarteDellaGuerraScenes (`../DellarteDellaGuerraScenes`)

All custom mission scenes. Key sub-folders:

- `SceneObj/` + `SceneEdit/` — scene data for every custom location (towns, castles, battlefields…)
- Scene-specific prefab assets (houses, walls, gate props, etc.) live here
- Scene-specific meshes and textures not shared with other modules also live here

## RuntimeDataCache Convention

`RuntimeDataCache/` is Bannerlord's compiled asset store. Generated by the editor/build pipeline from `Assets/` + `AssetSources/`. Appears in both `DellarteDellaGuerra` and `DellarteDellaGuerraMap`. Never edit manually — regenerate via the Bannerlord editor or Modding Kit.

## Controlled Dependency Modules

`Bannerlord.ExpandedTemplate` and `Bannerlord.Cannons` are DADG's own dependency modules,
embedded as **git submodules** under `src/submodules/` (declared in `.gitmodules`):

| Submodule | Path | Repo @ branch |
|-----------|------|---------------|
| Cannons | `src/submodules/Cannons` | `JoeFwd/Bannerlord.Cannons` @ `migrate-to-v1.3` |
| ExpandedTemplate | `src/submodules/ExpandedTemplate` | `JoeFwd/Bannerlord.ExpandedTemplate` @ `upgrade-to-1.3` |

Trace into them rather than treating them as black-box libraries. Edit their source **in place**
under `src/submodules/` — not the legacy standalone `Modules/Bannerlord.Cannons/` folder, which is
orphaned and is **not** the code the game runs.

### How submodule code reaches the game (build/deploy)

`DellarteDellaGuerra.Infrastructure.csproj` references the submodule projects via `ProjectReference`
(Cannons: API, main, Application, Domain, Infrastructure; ExpandedTemplate: API). So **building DADG**
compiles the submodules and copies their DLLs into `DellarteDellaGuerra.Core/bin/Win64_Shipping_Client/`
(plus `Gaming.Desktop.x64_Shipping_Client` and `Win64_Shipping_wEditor`). **That `bin/` is what the
running game loads** — there is no separate "deploy Cannons" step.

Consequence — to test a submodule change you must **rebuild DADG**, not just the submodule:

- The `x64 / Debug` config feeds `Win64_Shipping_Client`, which the Standalone debug config launches.
  Confirm the freshly-built `Bannerlord.Cannons.dll` timestamp in
  `DellarteDellaGuerra.Core/bin/Win64_Shipping_Client/` before trusting a test result.
- ⚠ Building `Bannerlord.Cannons.csproj` **standalone** has a copy target whose `GameFolder` resolves
  to `src`, so it deploys to `src/Modules/Bannerlord.Cannons/bin/...` — a dead-end the game never loads.
  A fresh DLL there does **not** mean the game picked up the change.

The `ExpandedTemplate` API is bound in `SubModule` constructor via `BannerlordExpandedTemplateApi().UseLoggerFactory(...).Bind()`.
